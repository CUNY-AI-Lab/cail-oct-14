Guiding Principles

Privacy by Design
We only work with Zero Data Retention providers, and with locally hosted models
Transparency
We favor open-weight models and make their licenses, abilities, and limits legible in our Model Registry
Environmental Accountability
We show estimated energy and carbon under every Sandbox query
Criticality
We try to build tools that open up how AI works and keep users’ judgment at the center
The four principles published on the Lab website (ailab.gc.cuny.edu), each with something we already do. - Privacy by Design, "we use providers that don't retain or train on user data": cloud models run only on zero-retention hosts, and material we shouldn't send out goes to the GPU server in the New Media Lab (slide 5). Faculty and researchers can use the service without adding their work to a provider's training data. - Transparency, "we prioritize open-weight models that can be examined and understood": click "Model Registry" to open it over the slide; Esc or the X closes it. The Model Registry (ailab.gc.cuny.edu/models) lists each model with its license, capabilities and known limits. Published weights let us get the same model from more than one provider. We offer a closed model only for a specific reason. - Environmental Accountability, "tools include visibility into computational costs": the Sandbox shows energy and carbon estimates under each response. They cover inference only, not training. - Criticality, "AI literacy over AI dependency": criticality is built into the infrastructure, not added as a lesson on top. Across the tools we try to make the technology legible and keep people doing the thinking, in the classroom and about AI itself. Examples to pick from: visible prompts and side-by-side comparison in the Sandbox, Agent Studio keeping sources and drafts in view, the Registry's stated limits, and published code anyone can inspect.

An overview of how we operate. The Lab grew out of centers that already worked closely with faculty, students and staff, each meeting particular needs over many years. We carry that habit into AI: we respond to people who come to us for help and support, not to wish lists. Keep it measured; the point is continuity and accountability, not scale. The diagram is a lighter version of the ACH "CALI to CAIL" chart, with the four centers given equal weight. Since 2022 each center took up generative AI in its own way; the Critical AI Literacy Institute (CALI), designed by the TLC with a three-year Google.org grant, was what brought that work under one banner. The TLC strand, if asked: Teach@CUNY AI Toolkit (2023), TLC workshops (2023 to 2024), communities of practice (2024 to 2025), then CALI (2025). The old chart framed the need as infrastructure that is private, secure and well scaffolded.

Where the Tools Run

Two ways in, three hosting arrangements, and model calls that cross them. Solid lines go through the Gateway or are run by the Lab; dashed lines go straight to a provider. - Ways in: for the cloud tools, people sign in with CUNY Login, apply (on their own or for a class, slide 9), and the front door then checks CUNY Login, access and allowance on every visit. For local work, people send a request and Lab staff review it before anything touches the GPU server. - Cloudflare Workers: PDF Accessibility, Agent Studio, Site Studio, Media Tools, and the Model Gateway itself, plus the sign-in front door. These tools reach models through the Gateway. The self-service Media Tools run here; speaker labels run in a Cloudflare container with no outside model. - AWS: the Sandbox (Open WebUI on ECS). It calls the Gateway and also keeps a direct Bedrock connection. The public website is also on AWS (Amplify). - New Media Lab: the local media pipeline (transcription, speaker labels, image description, OCR) runs on our own GPU server and sends nothing out; it is for material that shouldn't leave the GC, and Lab staff review requests for it. AI Use Disclosure (not drawn) is a static page on the same server and calls no model. - The Gateway serves only Workers AI and Amazon Bedrock, open-weight models with zero data retention. We no longer use OpenRouter or Fireworks. The conundrum: hosting and model calls don't line up. The AWS-hosted Sandbox reaches Bedrock both through and around the Gateway, and the local pipeline never leaves our hardware. Say aloud what fits the room: Cloudflare is an Enterprise account, and the AWS contract is close but not yet signed. Source: cail-knowledge-base (October 12) and the cail-gateway and cail-tools-admission repos. The Sandbox's direct Bedrock connection comes from the knowledge base, not a live check.

Sustaining and Sharing the Work

  • We publish most of our code so other universities can adapt and adopt it
  • We grant class access when the instructor brings a critical approach and can support their students, or when we can step in
  • We build a community of practice through fellowships that support classes and projects, and through workshops
  • We look for partners who understand CUNY’s procurement and find creative ways to work within it

Other universities have asked how CAIL provides model access and decides what to build. Commons In A Box is the CUNY precedent for packaging academic software that other institutions can run and change. CAIL hasn't assembled that kind of package yet. Class access: we open a class when the instructor brings a critical approach to AI and can support their own students, or when we know we can support the course ourselves. Our staff is small; graduate student fellows help us extend that support. Steve says more about class access in a moment (slide 9). Community of practice: graduate student fellows (a February to June 2026 cohort of four, and a 2026–27 call at $10,000 per fellow) test tools, support faculty and their classes, write documentation and help run workshops. Workshop series so far: Vibe Coding, run in spring 2026 (as Coding with Generative AI) and again in fall 2026 (foundations, building a prototype, a bring-your-own-project clinic); in fall 2026 also the Sandbox Series (getting started, knowledge collections, skills and tools) and three drop-in co-working sessions (October 29, November 17, December 3), all in the New Media Lab. Procurement: buying for a state university is slow and complicated. Every vendor sees CUNY as an appealing contract. The partners worth having understand the work we do and the limits CUNY works under, and are willing to find creative solutions inside them.

The Gateway is where Stefano's commitments become working rules. - Researchers can call every model from their own code with one key. - We can move a model to another provider without anyone changing their tools. - Nothing sits idle on Workers. The Sandbox runs on an always-on container on AWS, which costs money every hour whether or not anyone is using it. Providers are deliberately unnamed. Production currently serves Workers AI and Bedrock; OpenRouter is no longer behind the Gateway. The Sandbox still has older direct connections outside the Gateway, so the diagram shows the Gateway path, not every Sandbox route.

Applying for Access

  • People apply on their own or for a whole class
  • Everyone signs in with CUNY Login first
  • We review each application and set an allowance
  • Instructors share one link, and students join with it

Administration screens show sample data

Advance once: the public application form, then the administration queue. - The form is the live page at ailab.gc.cuny.edu/request-access. One application covers the Sandbox, API keys, the Studios and Media Tools. - Students at other campuses get in through a class. The instructor applies once, and after approval shares a class link. - In the queue we approve or decline, pick the allowance (standard $5 or plus $20 every 30 days) and set when access ends. A decline reason is emailed. - The queue screenshot comes from a local copy of the admission system with invented people and example.edu addresses, not real applicants.

Agent Studio and Site Studio

  • Researchers keep sources, files and drafts in one Agent Studio workspace
  • Faculty and students build and preview academic websites in Site Studio
  • Same sign-in and allowance as the other tools

CAIL Pi

  • Pi is an open-source coding agent for the terminal
  • Participants set it up with the Lab’s models in one command
  • Each person uses their own Lab key and allowance
  • We teach with it in this fall’s vibe-coding workshops
Stefano maintains CAIL Pi and can take questions on it. The released version (0.3.0) is one npx command that installs Pi and asks for the person's Lab API key. A version that signs in with CUNY Login in the browser is in progress and not released. The terminal is the barrier for many people; Agent Studio and Site Studio offer agent help in the browser instead. Closing: We can connect the Gateway to any provider that meets these rules, including a public one. Empire AI is the obvious candidate in New York. Keep this to a sentence or two.
