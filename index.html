Guiding Principles

Privacy by Design
We only work with Zero Data Retention providers, and with locally hosted models
Transparency
We favor open-weight models and make their licenses, abilities, and limits legible in our Model Registry
Environmental Accountability
We show estimated energy and carbon under every Sandbox query
Criticality
We try to build tools that open up how AI works and keep users’ judgment at the center
The four principles published on the Lab website (ailab.gc.cuny.edu), each with something we already do. - Privacy by Design, "we use providers that don't retain or train on user data": cloud models run only on zero-retention hosts, and material we shouldn't send out goes to the GPU server in the New Media Lab (slide 7). Faculty and researchers can use the service without adding their work to a provider's training data. - Transparency, "we prioritize open-weight models that can be examined and understood": click "Model Registry" to open it over the slide; Esc or the X closes it. The Model Registry (ailab.gc.cuny.edu/models) lists each model with its license, capabilities and known limits. Published weights let us get the same model from more than one provider. We offer a closed model only for a specific reason. - Environmental Accountability, "tools include visibility into computational costs": the Sandbox shows energy and carbon estimates under each response. They cover inference only, not training. - Criticality, "AI literacy over AI dependency": criticality is built into the infrastructure, not added as a lesson on top. Across the tools we try to make the technology legible and keep people doing the thinking, in the classroom and about AI itself. Examples to pick from: visible prompts and side-by-side comparison in the Sandbox, Agent Studio keeping sources and drafts in view, the Registry's stated limits, and published code anyone can inspect.

An overview of how we operate. The Lab grew out of centers that already worked closely with faculty, students and staff, each meeting particular needs over many years. We carry that habit into AI: we respond to people who come to us for help and support, not to wish lists. Keep it measured; the point is continuity and accountability, not scale. Infrastructure

One way in, the places the cloud tools run, and model calls that cross them. Solid lines go through the Gateway or are run by the Lab; dashed lines go straight to a provider. The local pipeline is on the next slide. - Ways in: for the cloud tools, people sign in with CUNY Login, apply (on their own or for a class, slide 11), and the front door then checks CUNY Login, access and allowance on every visit. - Cloudflare Workers: PDF Accessibility, Agent Studio, Site Studio, Media Tools, and the Model Gateway itself, plus the sign-in front door. These tools reach models through the Gateway. The self-service Media Tools run here; speaker labels run in a Cloudflare container with no outside model. - With a Lab key: API access works from any code or app, on a laptop, a server or another project, with the person's Lab key and allowance. CAIL Pi is one thing it serves: a coding agent in the terminal that reaches the Lab's models through API access. - AWS: the Sandbox (Open WebUI on ECS). It calls the Gateway and also keeps a direct Bedrock connection. The public website is also on AWS (Amplify). - The Gateway serves only Workers AI and Amazon Bedrock, open-weight models with zero data retention. We no longer use OpenRouter or Fireworks. The conundrum: hosting and model calls don't line up. The AWS-hosted Sandbox reaches Bedrock both through and around the Gateway. Say aloud what fits the room: Cloudflare is an Enterprise account, and the AWS contract is close but not yet signed. Source: cail-knowledge-base (October 12) and the cail-gateway and cail-tools-admission repos. The Sandbox's direct Bedrock connection comes from the knowledge base, not a live check.

The Local Pipeline

Our answer for material that shouldn't leave the GC, such as identifiable research data. Everything here is local: model weights are downloaded once, and no file leaves the machine while a job runs. It became a standing service on September 25, when a principal investigator asked for an IRB-approvable way to transcribe focus-group audio. - People send a request; Lab staff run the job on our own hardware in the New Media Lab: a Dell Pro Max workstation (Windows 11 with WSL2 and Docker; NVIDIA RTX 5000 Ada with 32 GB of GPU memory, about 128 GB of system memory) and Mac Studios. - Transcription and speaker labels are installed: faster-whisper served by Speaches, and pyannote speaker-diarization 3.1, lined up by a small router. The temporary working copy is deleted whether the job succeeds or fails. - Image description and OCR: the strongest open models that fit this card. Qwen3-VL 8B for descriptions (the same model family Media Tools uses in the cloud) and DeepSeek-OCR for text, which our earlier local setup ran. olmOCR 2 is the alternative for OCR. If asked about confidential data: the workstation itself then falls under CUNY's host controls (disk encryption, MFA, per-user audit logs, patching, physical security, backups). Those answers are still being confirmed before anything goes to an IRB.

Vibe Coding

Vibe Coding, Sandbox Series, co-working sessions

Other universities have asked how CAIL provides model access and decides what to build. Commons In A Box is the CUNY precedent for packaging academic software that other institutions can run and change. CAIL hasn't assembled that kind of package yet. Access: all Graduate Center students, faculty and staff can apply. Across the rest of CUNY, access comes mostly through classes (a few faculty and staff from other campuses have individual access). Class access: we open a class when the instructor brings a critical approach to AI and can support their own students, or when we know we can support the course ourselves. Our staff is small; graduate student fellows help us extend that support. Steve says more about class access in a moment (slide 11). Community of practice, our plan to scale. It includes, among others, graduate student fellows (a February to June 2026 cohort of four, and a 2026–27 call at $10,000 per fellow) test tools, support faculty and their classes, write documentation and help run workshops. Workshop series so far: Vibe Coding, run in spring 2026 (as Coding with Generative AI) and again in fall 2026 (foundations, building a prototype, a bring-your-own-project clinic); in fall 2026 also the Sandbox Series (getting started, knowledge collections, skills and tools) and three drop-in co-working sessions (October 29, November 17, December 3), all in the New Media Lab. Procurement: buying for a state university is slow and complicated. Every vendor sees CUNY as an appealing contract. The partners worth having understand the work we do and the limits CUNY works under, and are willing to find creative solutions inside them.

The Gateway is where Stefano's commitments become working rules. - Researchers can call every model from their own code with one key. - We can move a model to another provider without anyone changing their tools. - Nothing sits idle on Workers. The Sandbox runs on an always-on container on AWS, which costs money every hour whether or not anyone is using it. Providers are deliberately unnamed. Production currently serves Workers AI and Bedrock; OpenRouter is no longer behind the Gateway. The Sandbox still has older direct connections outside the Gateway, so the diagram shows the Gateway path, not every Sandbox route.

Applying for Access

  • People apply on their own or for a whole class
  • Everyone signs in with CUNY Login first
  • We review each application and set an allowance ($5 or $20 a month)
  • Instructors share one link, and students join with it

Administration screens show sample data

Advance once: the public application form, then the administration queue. - The form is the live page at ailab.gc.cuny.edu/request-access. One application covers the Sandbox, API keys, the Studios and Media Tools. - Students at other campuses get in through a class. The instructor applies once, and after approval shares a class link. - In the queue we approve or decline, pick the allowance (standard $5 or plus $20 every 30 days) and set when access ends. A decline reason is emailed. - The queue screenshot comes from a local copy of the admission system with invented people and example.edu addresses, not real applicants.

CAIL Pi

  • Pi is an open-source coding agent for the terminal
  • Participants set it up with the Lab’s models in one command
  • Each person uses their own Lab key and allowance
  • We teach with it in this fall’s vibe-coding workshops
Stefano maintains CAIL Pi and can take questions on it. The released version (0.3.0) is one npx command that installs Pi and asks for the person's Lab API key. A version that signs in with CUNY Login in the browser is in progress and not released. The terminal is the barrier for many people; Agent Studio and Site Studio offer agent help in the browser instead. Closing: We can connect the Gateway to any provider that meets these rules, including a public one. Empire AI is the obvious candidate in New York. Keep this to a sentence or two.
