Infrastructure Decisions

Stefano Morello

American Social History Project / Center for Media and Learning

Guiding Principles

Privacy by Design
We send work only to zero-retention hosts, or keep it on our own GPU server
Transparency
We favor open-weight models and list each one’s license, abilities and limits in the Model Registry
Environmental Accountability
We show estimated energy and carbon under every Sandbox response
Criticality
We teach how models work in workshops, and students compare them side by side
The four principles published on the Lab website (ailab.gc.cuny.edu), each with something we already do. - Privacy by Design, "we use providers that don't retain or train on user data": cloud models run only on zero-retention hosts, and material we shouldn't send out goes to the GPU server in the New Media Lab (slide 5). Faculty and researchers can use the service without adding their work to a provider's training data. - Transparency, "we prioritize open-weight models that can be examined and understood": the Model Registry (ailab.gc.cuny.edu/models) lists each model with its license, capabilities and known limits. Published weights let us get the same model from more than one provider. We offer a closed model only for a specific reason. - Environmental Accountability, "tools include visibility into computational costs": the Sandbox shows energy and carbon estimates under each response. They cover inference only, not training. - Criticality, "AI literacy over AI dependency": fall workshops and the fellows cohort, side-by-side model comparison in the Sandbox (slide 16), and course configurations students can question (slide 17).

Sustaining and Sharing the Work

  • We publish most of our code so other universities can adapt it
  • We review a tool more closely as more people rely on it
  • We need staff, not just licenses, to keep these services running
Other universities have asked how CAIL provides model access and decides what to build. Commons In A Box is the CUNY precedent for packaging academic software that other institutions can run and change. CAIL hasn't assembled that kind of package yet. A classroom experiment and a system that touches student records shouldn't get the same review. Buying one AI product still leaves a university responsible for data protection, access, faculty support, documentation and the option to leave. That work takes staff.

The Gateway is where Stefano's commitments become working rules. - Researchers can call every model from their own code with one key. - We can move a model to another provider without anyone changing their tools. - On Workers we pay only for the requests that come in. An always-on container on AWS, which is how the Sandbox runs, costs money every hour whether or not anyone is using it. Providers are deliberately unnamed. Production currently serves Workers AI and Bedrock; OpenRouter is no longer behind the Gateway. The Sandbox still has older direct connections outside the Gateway, so the diagram shows the Gateway path, not every Sandbox route.

Applying for Access

  • People apply on their own or for a whole class
  • Everyone signs in with CUNY Login first
  • We review each application and set an allowance
  • Instructors share one link, and students join with it

Administration screens show sample data

Advance once: the public application form, then the administration queue. - The form is the live page at ailab.gc.cuny.edu/request-access. One application covers the Sandbox, API keys, the Studios and Media Tools. - Students at other campuses get in through a class. The instructor applies once, and after approval shares a class link. - In the queue we approve or decline, pick the allowance (standard $5 or plus $20 every 30 days) and set when access ends. A decline reason is emailed. - The queue screenshot comes from a local copy of the admission system with invented people and example.edu addresses, not real applicants.

Agent Studio and Site Studio

  • People hand the agent a whole task
  • Researchers keep sources, files and drafts in one Agent Studio workspace
  • Faculty and students build and preview academic websites in Site Studio
  • Same sign-in and allowance as the other tools
Advance once to swap Site Studio for Agent Studio. Site Studio is still the HTML mock-up from the ACH deck. The Agent Studio workspace is a real screenshot of the current app, taken October 13 from a local run. Its panels hold real OpenAlex results (search "generative AI" "higher education"), placed there directly rather than produced by the agent, and the prompt in the chat box was typed for the picture, not sent.

CAIL Pi

  • Pi is an open-source coding agent for the terminal
  • Participants set it up with the Lab’s models in one command
  • Each person uses their own Lab key and allowance
  • We teach with it in this fall’s vibe-coding workshops
Stefano maintains CAIL Pi and can take questions on it. The released version (0.3.0) is one npx command that installs Pi and asks for the person's Lab API key. A version that signs in with CUNY Login in the browser is in progress and not released. The terminal is the barrier for many people; Agent Studio and Site Studio offer agent help in the browser instead. Closing: We can connect the Gateway to any provider that meets these rules, including a public one. Empire AI is the obvious candidate in New York. Keep this to a sentence or two.
